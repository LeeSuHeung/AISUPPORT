# 구파발게임 개발팀

- 사용자가 `구파발게임` 또는 정확한 역할 이름을 명시하지 않으면 구파발 Skill이나 역할 에이전트를 사용하지 않는다.
- 실제로 열린 프로젝트의 파일과 사용자가 명시한 요구사항만 대상으로 작업한다. 검증을 위해 가상의 기능, 코드, 아트 에셋, 목업을 만들지 않는다.
- 사용자가 `구파발게임`이라고 말하면 `$gupabal-game` Skill을 직접 호출한 것으로 처리한다.
- 한 분야만 필요한 작업에는 해당 전역 에이전트를 단독으로 사용한다.
  - 시스템·규칙·성장·경제·수치 밸런스: `구파발기획자`
  - 아트 방향·UI 시각 체계·캐릭터·환경·에셋 규격: `구파발아트디자이너`
  - 화면·입력·렌더링·플랫폼·네트워크 연동: `구파발클라이언트`
  - 권위 상태·API·DB·동시성·보안·운영: `구파발서버`
- 둘 이상의 분야가 함께 결정해야 하는 게임 작업에는 `$gupabal-game` Skill을 사용한다.
- 메인 Codex는 각 역할의 독립 제안을 받은 뒤 질문과 답변을 서로 전달하고, 합의·충돌·미결정을 구분해 기록한다.
- 합의된 시스템 규칙, 클라이언트/서버 계약, 아트/클라이언트 전달 규격, 역할별 소유 파일을 정하기 전에는 구현을 시작하지 않는다.
- 여러 에이전트가 동일한 파일을 동시에 수정하지 않게 한다.
